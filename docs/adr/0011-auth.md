# 0011. Authentication: dashboard sessions and API keys

- Status: Accepted
- Date: 2026-09-28

## Decision
- Passwords: argon2id
- Dashboard: JWT access token (15 min) in memory + opaque refresh token in `httpOnly`, `Secure`, `SameSite=Lax` cookie
- Refresh tokens stored hashed, grouped in a family; each use rotates; reuse revokes the family
- API keys: `po_test_<id>_<secret>` with 32 random bytes; stored as SHA-256 of the secret
  (high-entropy secret, so a fast hash is safe; slow hashes are for human passwords), compared in constant time
- Two guards: `DashboardAuthGuard`, `ApiKeyGuard`; `@Roles()` for member vs owner
- Ownership ("only your charges") checked in use cases, not only in guards

## Consequences
- Stolen DB does not expose usable keys or passwords
- API key verification stays fast on every request
